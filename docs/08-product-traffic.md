# 连续混合需求评估 · 题目2

用户要求按产品上线后的多运营连续需求验证，避免每种情况都单独清空数据库。这里新增固定种子的到达流和独立抽样的服务健康事件，混合新任务、重复、同ID改条件、运营复核（题1）及外部占位（题1）。固定流量先生成，Agent才执行；不按观察结果倒填理想预期。只在模拟运营确认事件中读取先前实际建议并记录明确批准参数。

实际为合成串行回放，不是真实生产日志、并发压测或真实模型统计。输入为旧产品原有结构化表单，未新增自然语言需求解析。每一天使用不同共享数据库，两天互相独立；单日不是每条新建库。fault为模拟工具故障，和需求类型独立，不代表真实服务故障率。

规划两天仅25/96条达到completed目标；42条预算/时间不可行（第1天25、第2天17）、17条缺输入、6条同ID变更拒绝、5条无资料、1条工具失败，共71条未完成。预算0/5、20分钟截止等苛刻需求占比是预设合成流量分布，不是实际线上比例；没有用安全检查全过掩盖低业务完成数。保留失败计费和已有结果，每任务预算独立；该模拟不实现全公司共享钱包、并发产能排队或同ID原地改预算，补齐硬条件需新ID，真实产品需要进一步设计修订体验。

当前36个回归测试通过，包含流量固定种子/前缀一致性和监测器发现伪造保存/计费的测试；[实际日志](../examples/traffic/regression-tests.txt)。监测同时核对权限/预算/依赖、账本与保存回执、相关旧状态保留和重复唯一约束。它不检测全部业务语义，也不把“草稿写入成功但仍待确认”当成完整业务目标。

新增harness的开发验证中发现了重复外部排期ID及把随机attempt ID排序误当时间排序的问题，修正监测器后重放；没有修改核心Agent或改写旧真实模型记录。两天最终记录所用src与基线`81caf29b4f56ec328788871791f7d2fda35d1231`一致；历史summary的完整摘要包含当时的测试/脚本，因此不要求与新增评估后的总摘要相同。

真实连续流量尚未执行，用户选择在题3/题4准备后统一运行。仓库支持CLI --model live；外部统一入口会只在本机窗口取一次密钥，进程环境传递，不写入文件。后续结果必须另存并据实际状态更新，不把Mock的96/96边界检查说成真实Agent完成96/96需求。
