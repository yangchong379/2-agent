# 05 实现复盘、用时与下一步

本页由AI依据当前真实实现与验证整理，用户实际操作和AI辅助分别记录，不代替候选人尚未发生的独立编码经历。

## 最难的问题

核心难点是剩余计划与沉没费用的一致性。若检索已花4、生成失败花1，再选择报价8的轻量方案，最终并不是8：应复用检索结果，只加剩余脚本5和保存1，得到11。实现将基础报价、剩余费用和预计总费用分开，账本保留失败尝试，并使估算版本与实际状态绑定。

另一个难点是“失败步骤可续跑”与“重复执行不重复收费”同时成立。仅保存最后文本会丢失依赖与失败费用；重跑全流程会再次检索和生成。这里持久化每个步骤、尝试及费用，成功步骤返回REUSED，未成功步骤在新估算和依赖满足后再执行。同一run的方案唯一，重复完成请求新增费用0。

## 工程取舍与收获

- 模型负责选择方案和动作，代码负责预算、截止时间、依赖与真实状态；Mock不是模型效果证明。
- 每次收费尝试后重新估算，可让失败费用和成功成果进入下一轮决策，不沿用过期预测。
- 费用、时间、输出和保存方案须在同一事务内提交；保存插入异常时，不能只回滚文件却保留扣费。
- 真实评估与离线评估分目录，保留源码摘要。后续模型若失败，先解释真实失败原因，再修改和定向重跑，不改写原始失败记录。
