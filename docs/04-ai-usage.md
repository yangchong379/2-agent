# 04 AI辅助范围与个人贡献

## 分工

| 环节 | 用户/候选人 | AI辅助 |
|---|---|---|
| 需求与范围 | 提供内容任务规划题目，明确新建独立项目并保留前一项目，确认题号2 | 拆解验收点、设计方案与工程实现 |
| 模型接入 | 在本机窗口输入密钥，启动真实评估 | 提供本机连接脚本、核对协议、记录验证边界 |
| 运行与反馈 | 在本机启动真实评估，核对项目目录，保留首轮失败，之后重跑三项网络传输失败并反馈 3/3 通过 | 执行离线测试、读取实际产物、核查成本与状态 |
| 连续需求评估 | 提出共享状态下的连续混合需求，确认启动联合评估并在本机输入密钥，要求逐条整理输入、输出和流程 | 实现流量模拟和评估程序，核对费用、步骤依赖、重跑与保存状态 |
| 代码与文档 | 本轮未记录独立手写代码量和独立编码工时 | 实现Python源码、合成数据、测试、评估器、文档及交付脚本 |
| GitHub | 提供独立仓库yangchong379/2-agent | 整理提交、推送与远端校验 |

本人在这个新项目中的已知贡献是提供需求、确认范围、选择独立交付、提供仓库以及本机真实评估操作。前一项目的历史经验可用于学习，但不把前一项目的测试或个人操作冒充本项目已经完成的验证。

## 技术复用范围

复用了同会话素材审核项目中的通用HTTP工具调用协议处理、原调用ID回传、协议拒绝反馈和Windows密码窗口，复制后调整为本仓库的run_id、工具定义及模型提示；无跨目录依赖。预算估算、整数模拟计费、步骤依赖、持久状态、续跑和方案保存为本项目独立实现。

没有使用Agent框架或多Agent。Python版本、依赖与运行命令均在README说明。业务工具采用本地合成函数，生成脚本是标明synthetic的模板结果，不将其称为真实创作模型效果。

## 验证及当前结果

AI实际执行34个自动化测试和13组离线场景，全部通过；产物见[离线报告](../examples/runs/mock/REPORT.md)及[测试明细](../examples/runs/mock/tests.txt)。真实评估由用户在本机启动，deepseek-flash首轮10/13通过，三组有MODEL_TRANSPORT_FAILED；用户之后在本机完成三项定向重跑，3/3通过。[真实原始报告](../examples/runs/live/REPORT.md)与[AI复核](../examples/runs/live/REVIEW.md)保留首轮失败。[重跑复核](../examples/runs/live-retry/REVIEW.md)及[两轮汇总](../examples/runs/LIVE-REVIEW.md)记录同源码累计13类场景有通过证据，不能称一次全量13/13。

模拟费用使用持久账本计算，失败费用不抹除，成功结果不重扣。测试覆盖预算12超10改8、失败后复用素材、跨进程续跑、重复执行0新增费用、SQL保存回滚等。所有示例输出由代码执行产生，不手工把失败改成通过。

密钥只由用户在本机输入，运行结束清理进程环境；不写入源码、输入、Trace或Git。模型内部思考字段仅必要时在内存回传；Trace只含短行动依据和工具事实。

## 后续补记方式

本轮2026-11-04真实首轮10/13及定向重跑3/3已据实际文件补记；用户负责本机运行和结果反馈，AI负责账本/Trace核查及文档上传。未因网络问题修改运行源码，重跑输入、输出及原始失败均保留。以后产生新模型记录时继续保留原始失败及源码摘要；若候选人自行更改代码，应以实际文件差异及本人运行命令说明。独立用时未记录时保持未知，不使用AI墙钟时间代替个人编码工时。
